# Pareto Executor

## Goal
To rigorously execute the code simplification and reduction tasks defined in `PARETO_AUDIT.md` and `PARETO_PLAN.md`. This skill transforms the analysis into action while ensuring the project remains compile-ready and functional at every step.

## When to use this skill
- Immediately after `pareto-simplifier` has generated the audit and plan files.
- When the user asks to "apply the changes", "start the cleanup", or "execute the pareto plan".
- When a `PARETO_PLAN.md` file exists in the root or `.agent` directory.

## How to use it
1.  **Read Context**:
    -   Locate and read `PARETO_AUDIT.md` (to understand the *why*) and `PARETO_PLAN.md` (to understand the *how*).

2.  **Assess Workload**:
    -   Evaluate the complexity of the steps listed in `PARETO_PLAN.md`.
    -   **Decision Point**: Can this be done in one turn?
        -   *Yes*: Proceed to execute all steps.
        -   *No (Too massive)*: Select a logical subset of steps (e.g., "Phase 1: Delete unused files" or "Phase 2: Refactor GUI handlers").

3.  **Execute Changes**:
    -   Apply the changes (deletions, refactoring, merging) strictly following the plan.
    -   **Important**: After every significant change (or batch of changes), verify that the code still compiles and (if possible) logically holds together.

4.  **State Management (Crucial)**:
    -   **If Partial Execution**:
        -   Mark completed steps as DONE in `PARETO_PLAN.md` or remove them from the list.
        -   Update the file to reflect the current state (e.g., "Remaining steps: ...").
        -   Inform the user: "I started the massive task. Steps 1-5 are done. Run me again to continue."
    -   **If Full Execution (Completion)**:
        -   Verify all steps are done.
        -   **DELETE** `PARETO_AUDIT.md`.
        -   **DELETE** `PARETO_PLAN.md`.
        -   Inform the user: "Simplification complete. Plan files have been cleaned up."

## Decision Logic
-   **Is the plan huge (e.g., > 10 complex refactors)?** -> Do the first 3-5, update the plan file, stop and ask to continue.
-   **Is the plan moderate?** -> Do it all in one shot.
-   **Did a step fail (compilation error)?** -> Stop, revert that specific step, mark it as FAILED in the plan, and ask for manual review or `bug-fixer` intervention.

## Examples
**Scenario: Massive Cleanup**
*Plan has 20 steps.*
**Agent:** "This is a large operation. I will execute steps 1 through 5 (File deletions and basic merging)."
*Agent performs actions...*
*Agent updates `PARETO_PLAN.md` removing steps 1-5.*
**Agent:** "I have completed the first phase. Please invoke me again to continue with the remaining steps."

**Scenario: Quick Fix**
*Plan has 2 steps.*
**Agent:** "Executing full plan."
*Agent performs actions...*
*Agent deletes `PARETO_AUDIT.md` and `PARETO_PLAN.md`.*
**Agent:** "All cleanup done. Plan files deleted."

## Constraints
-   **Compilation is Law**: Do not leave the project in a broken state between partial steps if possible.
-   **Update vs Delete**: NEVER delete the plan files unless the job is 100% finished.
-   **Iso-functionality**: Maintain user features.
